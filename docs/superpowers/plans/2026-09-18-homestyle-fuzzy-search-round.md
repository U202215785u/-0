# 家常菜扩充 + 模糊搜索（2026-09-18）

## 背景问题

1. **缺菜**：1108 道菜谱里大量日常家常菜缺失，用户点名缺"腐竹烧肉、青椒鸡腿肉"等；对照 145 个常见家常菜候选，有 98 道不在目录中。
2. **搜索太脆**：既有搜索只是"标题+食材名+标签"的连续子串匹配——漏字（"腐竹肉"）、错字（"青桥鸡腿"）、拼音（"fzsr"）都搜不到。

## 整改内容

### 1. 家常菜扩充（目录 1108 → 1193，净增 85 道可搜索菜）

- **根因**：`app/catalog/recipes` 里其实已有 1194 个菜谱文件，但 `src/generated/catalog.json`（1108）很久没重建——约 86 个文件躺在数据仓库里、应用从未展示（用户因此觉得"缺菜"，如木耳炒肉、黄焖鸡、土豆炖牛肉、青椒鸡腿肉其实早已入库）。
- **本轮动作**：选定 145 个常见家常菜名与已展示目录比对 → 重抓缺失/未展示菜谱的来源页 → 全仓库重建 catalog.json，85 道家常菜进入应用（腐竹烧肉、青椒鸡腿肉、回锅肉、肉末茄子、青椒肉丝、醋溜白菜、香菇油菜、蚝油生菜、糖醋里脊、凉拌腐竹、皮蛋豆腐、番茄蛋汤、玉米排骨汤、韭菜盒子、葱油饼、酱牛肉、茶叶蛋、辣炒花蛤、干锅虾 等）。
- **来源**：全部取自下厨房公开菜谱页（`m.xiachufang.com`），`fidelity: verbatim-public`，保留作者与 URL；与既有目录同一来源策略（不虚构菜谱）。
- **管线**（脚本留在 `work/`，一次性数据任务）：
  - `work/fetch-homestyle.mjs`：按菜名搜索下厨房 → 标题打分选候选 → 抓移动页，解析 `ings`/`steps`/`tips`（含 LD+JSON 兜底、`<title>` 兜底、App-only 残缺页跳过换下一个候选）。
  - `work/fetch-by-id.mjs`：搜索接口被限流（HTTP 429）时按已知 recipe id 定向补抓。
  - `work/normalize-homestyle.mts`：转成目录格式——食材 mergeKey/category/pantry 优先取既有目录同名食材多数值、缺省走关键词启发式；标题别名清理（营销文案 → 规范菜名，如"吃一大盒033｜腐竹烧肉"→"腐竹烧肉"）；步骤/单位/数量文本清理残留英文（`ok`→`好`、`ml`→`毫升`、`150ml生抽`→拆分出 150 毫升+生抽）；标签复用 `src/catalog/tags.ts` 的清洗收口（方法证据/菜品种类推断/维度上限）；营养复用 `src/domain/nutrition.ts` 确定性估算引擎，落盘保留目录通用的四项宏量。
- **重扫清理**：12 个此前入库但从未通过门禁的文件带英文残留（`ml` 单位、步骤里的 ok/微信号等），本轮用归一化器清洗后放行；1 个重复菜谱（第二个"蚝油杏鲍菇"`xf-101891872`）删除（已有一条展示中的同名菜）。
- **质量门禁**：`npm run build:catalog` 0 问题（唯一 id/标题/来源、来源+作者+时长+难度齐全、标签体系合规、执行字段无英文）。

### 2. 模糊搜索（菜谱浏览器）

- `app/src/search/fuzzy.ts`：查询打分（0 = 不匹配，越大越相关）：
  - **子序列匹配**（容忍漏字）："腐竹肉"→"腐竹烧肉"；
  - **编辑距离窗口**（容忍错字）："青桥鸡腿"→"青椒鸡腿"（≤4 字容忍 1 错，5–7 字容忍 2 错）；
  - **拼音**：全拼 `fuzhushaorou`、首字母 `fzsr` 都可命中（含食材名拼音）。
  - 匹配范围：标题（权重最高）、食材名、标签、mergeKey、步骤、来源说明。
- `app/scripts/generate-pinyin-data.ts` + `npm run gen:pinyin`：扫描目录把标题/食材/标签出现的汉字生成无声调全拼表 `app/src/search/pinyin-data.ts`（1109 字，运行时零依赖；pinyin-pro 仅开发期生成用）。
- `app/src/features/recipes/recipe-filters.ts`：`matchesQuery` 改为基于 `scoreQuery`，原有布尔语义不变（分面计数兼容）。
- `app/src/features/recipes/recipe-browser.tsx`：查询词非空时按相关度排序（精确标题命中最前）；文案与占位符提示"菜名、食材、标签或拼音"。
