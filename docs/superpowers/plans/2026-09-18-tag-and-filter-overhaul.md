# 标签与筛选系统整改（2026-09-18）

## 背景问题

整改前 1108 道菜谱的标签是自由文本、无维度约束的产物，存在三类乱象：

1. **词表混乱**：18 个标签混用，"烧焖/烧/炖"并存、"汤羹/汤底"并存；"快手"与"快手菜"两种写法。
2. **标注失真**：汤菜被标"烤"、凉拌菜被标"烧焖"、面包被标"炸"；皮蛋烧鸭粥一类粥品挂了 6 个标签；45 道汤菜漏标"汤羹"。
3. **筛选简陋**：页面只有一个扁平的标签横条（标签为"烹饪方式"但混入非做法标签），标签之间全 AND 语义，无数目、无难度/用时筛选项，也无清除入口。

## 整改内容

### 1. 标签体系（单一事实源）— `app/src/catalog/tags.ts`

- 16 个规范标签，分 4 个维度，每维度有数量上限：

| 维度 | 标签 | 上限 |
| --- | --- | --- |
| 烹饪方式 method | 炒 煮 蒸 炸 煎 烤 炖 烧焖 凉拌 | 1 |
| 菜品种类 dishType | 主食 汤羹 点心 | 1 |
| 特点 feature | 家常菜 快手菜 | 2 |
| 饮食偏好 diet | 素菜 减脂高蛋白 | 1 |

- 单菜标签总数 ≤ 4。
- 旧写法别名映射：烧→烧焖、汤底→汤羹、快手→快手菜、凉菜/凉拌菜→凉拌 等。
- 工具函数：`sanitizeTags`（别名/去重/清洗）、`normalizeRecipeTags`（维度收口）、`cleanRecipeTags`/`resolveRecipeTags`（数据清洗，含标题推断菜品种类与步骤做法证据裁剪）。

### 2. 质量门禁 — `app/src/catalog/quality.ts`

构建时校验每个菜谱的标签：体系外标签、重复、同维度溢出、总数超限都会让 `npm run build` 失败，保证新数据不再回潮。

### 3. 数据整改（1108 道菜全量重打）

- 生成紧凑批次 → 23 个并行精修子任务依据步骤动词/标题/时长重写标签（宁缺毋滥）→ 合并回 `app/catalog/recipes/*.json` → 确定性卫生后置兜底（`clean-tags.ts --apply --keep-methods`）。
- 复垦工具：`app/scripts/clean-tags.ts`（`--report` 预览 / `--apply` 落地）、`work/retag/`（prepare/merge/verify）。

### 4. 筛选系统重做

- `app/src/features/recipes/recipe-filters.ts`：结构化筛选（关键词 + 各维度标签 + 难度 + 用时区间）。
- 同维度多选 = OR，跨维度 = AND；难度、用时为单选；全维度可组合。
- `app/src/features/recipes/recipe-browser.tsx`：按维度分组展示标签（烹饪方式/菜品种类/特点/饮食偏好）+ 难度 + 用时；每个筛选按钮带分面计数角标（考虑其余已选条件）；支持"清除全部筛选"与结果计数；空结果给出一键清除。
- `recipe-detail.tsx`：标签按维度分组展示（如「烹饪方式：烧焖」「特点：家常菜」）。

## 维护约定

- 新增菜谱只允许使用 16 个规范标签，且不得超过维度上限；`npm run build` 会强制校验。
- 想调整词表（增删标签）请先改 `app/src/catalog/tags.ts`（含别名与上限），再跑 `clean-tags.ts --apply` 全量清洗并重建 catalog。
- 已校验结果：整改后标签满足体系约束（门禁 0 问题），恢复"炒/烧焖"等大头做法的合理分布，删除汤类误标"烤"等失真标签。

## 验证
